## Credential recovery follow-up

Later on 2026-11-09, the maintainer's other Mac was checked through Local MCP. Its original local publishing configuration still contained all three platforms, and the maintainer authorized copying it to the current Mac. The earlier missing-local-configuration finding applied only to the initial publishing environment, not both machines.

Chrome's recovered credentials passed token exchange and draft read. Firefox's credentials passed an authenticated private-profile read; the version list then contained no 1.5.0. Edge configuration was recovered, but the existing script's `/v1/products` endpoint returned HTTP 401. The earlier comparison against `/v1.1/products` was not a valid endpoint check: Microsoft's "v1.1" labels ApiKey authentication, while its [full URL examples](https://learn.microsoft.com/en-us/microsoft-edge/extensions/update/api/using-addons-api#uploading-a-package-to-update-an-existing-submission) still use `/v1/products`. The 404 on the undocumented route does not indicate operation expiry. Credential values and private storage locations are not in this repository.

Google Cloud/OAuth authorization remained valid; the missing store declaration was a separate condition.
